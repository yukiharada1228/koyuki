# 入れ子の段階から、要求型に文脈を混ぜない

購買Applicationに残っていた、申請編集・返品・数量訂正のload型引数指定3箇所を削除した。
これで25操作の宣言に、操作別loadの型引数指定は残らない。最初の15箇所から0箇所になった。
I/O adapterの境界型、通常の業務関数の型宣言まで不要になったという意味ではない。

```ts
edit: { load: context.request, run: [checkBuyerRequest,
  step('require-draft', checkRequestEdit),
  step('parse-lines', parsedRequestInput), step('edit-request-plan', editPlan)] }

return: { load: context.receipt, run: [checkReceipt,
  step('run:2', returnDecision), step('run:3', includeChangedStock)] }
```

## 要求と、途中のinputを区別する

withInput等の後段では、`input`が元の業務文脈全体を指す。
全段階のinput型を一度に交差すると、その文脈のactor・current・検証済みの証明等を、呼出し元の要求にも混ぜてしまう。
要求を段階の先頭から蓄積し、候補から取得した文脈が全段階を接続できる時点で収集を止めるようにした。
必要な項目が別々の段階に現れる場合は、その分を蓄積してから候補を採用する。

各候補では、要求がloadの入力条件を満たすこと、取得結果が元の文脈を保つこと、実際のloadがその要求で文脈全体を保証することを確認する。
さらに、全段階で前の実際の出力を受け取れることを確認する。後段の期待型だけでloadへ状態や証明を追加しない。
既に接続できる関数列は元の要求型を保つ。

## bounded genericの型を先に取り出す

generic関数の引数をオブジェクト全体の条件型から取り出すと、今回の例では比較が保留される。
要求型は、先に取り出した引数型のinputプロパティをキー経由で参照する。
段階の入力比較も、引数型を独立した型引数として先に束縛してから行う。
比較式自体は従来と同じ`[C] extends [P]`であり、代入可能性やvarianceを緩めてはいない。

実行処理、業務ルール、保存計画、公開APIは変更しない。
coreと購買ApplicationのTypeScriptを変換したJavaScriptが、変更前と一致することも確認する。

## 確認範囲

[専用契約](../src/business-request-prefix.test.ts)は、次を検査する。

- 通常の検証・状態の絞り込み・名前付きのgeneric解析・状態生成を、そのまま配列へ並べる。
- 呼出し元の要求にactor等を含めず、reason・raw等の必要項目を保つ。unknown型の項目も必須のままにする。
- 状態拒否を解析失敗より優先し、失敗後は状態生成・保存を実行しない。
- privateな認可、呼出しシグネチャ、直和の各variantの事実を、存在しない文脈へ補わない。
- 必須プロパティと任意プロパティを区別し、空のオブジェクト型にもnullを通さない。

[配布物検査](../scripts/test-business-package.mjs)には、入力型の先行束縛・キー参照・先頭からの要求収集を、それぞれ以前の比較へ戻す対照を含める。
全段階の要求を交差する対照は、平らな関数列を引き続き受理しつつ、入れ子の文脈を持つ正例で失敗することを確認する。
従来のload全体の保証、検証の証明、閉じたエラー集合等の拒否契約も維持する。

以前の「request保持のgateを外すと特殊化済みloadの正例が失敗する」という必須対照は、先頭からの要求収集後は違いを検出しなくなった。一時コピーでgateを外しても全ソースの型契約が通ることを確認し、この必須失敗の判定を外した。製品のgate、特殊化済みloadの正例、実際のload保証を外した際の拒否対照は残す。特定の旧不具合による失敗を永続的な仕様にはしない。

[長い要求の検査](../scripts/check-request-prefix-scale.mjs)では、62個の独立した要求項目が別々に現れる64段階の宣言を生成する。
実tarballのSDKで型検査と実行を行い、最後の要求項目も必須であること、宣言した全エラー型を保持すること、load・64段階・saveがそれぞれ一回だけ実行されることを確認する。
これは対象例の検査であり、任意の関数列の長さや型計算の性能を保証するものではない。

講演全体の完全実現、名前なしinline、任意の深いgeneric変換や原音確認の完了を示すものではない。
AI試用の後続改善であり、新たな独立利用者の試用として数え直さない。
