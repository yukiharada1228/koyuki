# Koyuki 0.1.0-alpha.6

0.1.0-alpha.6の変更と移行上の注意。alpha.5以前のパッケージには実験APIは含まれない。公開状況はnpm registryとGitHub Releaseで確認する。

## この候補で追加・改善したこと

- `koyuki/experimental`のTemplate・Context・Hooks・JSXで業務ツリーを構成し、Actorを実行スコープで供給。
- Guardで配下の操作・Query・イベント受信を認可し、実行完了通知と配送記録でdenied / defectを区別。
- generic saveの成功値を精密に保持し、広い保存結果を誤って狭めない型契約。
- 予約のID分離、日程変更の競合・永続再送、キャンセル手数料・返金イベントの追加検証。
- 予算付き経費精算、多段階承認・差し戻し・予算確保/解放・原子的な監査とoutbox・receipt、通常TypeScriptとの比較。
- Quick Startを一つの推奨導線に統一し、独立したtarball consumerでTS6/7・宣言生成・実行を確認。

過去からのUnreleasedの全変更は[CHANGELOG](../../CHANGELOG.md)も参照する。本案は今回のコミット整理・CI候補の要点であり、過去の全履歴をこの節だけで網羅したという意味ではない。

## 移行上の注意

- 実行完了とイベント配送のstatusに`denied`を追加。網羅的な分岐ではこのケースを扱う。Guard拒否は業務Resultのエラーへ暗黙に混ぜず、`ExecutionDenied`でrejectする。
- 推奨サンプルの`createBookingApp`はRepositoryだけを受ける。Actorは`.scope(children => <Actor.Provider ...>)`で供給する。これはサンプルの変更で、既存`createApplication`は保持する。
- 日程変更と手数料付きキャンセルはrequestIdを要求し、成功値はcommitted / replayedを区別する。再送にはアダプター側の原子的な保存が必要。
- ID生成関数は検証のResultを返す。BookingIdとActorIdを取り違えず、外部値とDB復元値を検証する。
- generic saveの型精度の変更で、以前の広い型を前提にした注釈や不正な接続がコンパイルエラーになる場合がある。

## 保証範囲と制約

コアはWeb標準API・実行時外部依存ゼロ。Node SQLiteはサンプル/ホスト用であり、コアの依存ではない。Hooksはスコープ構成時の依存取得で、Reactの再描画機構ではない。各scopeでハンドラーを組み立て、共有Contextを差し替えない。

DBの競合検出、transaction、outboxのack・保持期間、外部返金・通知の重複排除はホストとの契約。外部配送のexactly-once、任意関数の純粋性、業務仕様の自動推測は保証しない。閾値変更の比較ではKoyukiと通常TSの接続変更量は同等であり、常に少ないコードや高い生産性を主張しない。

実験APIは変更され得る。実運用負荷、人間の初見学習、大規模チームの生産性は未実証。[Quick Start](../../examples/authoring-quickstart/README.md)、[保存と比較の詳細](../expense-budget-study.md)、[ローカルのコミット検証記録](../commit-review.md)を参照する。
