ユーザーから整理を任されたことを受け、逐語的な聞き取りと実装判断を分離する。
これは原音を聞いた記録ではない。既存のneedsDirectAudioとaudioDirectlyReviewed:falseは維持する。
確認者・聞き取った文言を推測で記入しない。

## 今後の進め方

この10区間の文言確認だけを、既に根拠のある実装・検証全体の停止条件にはしない。
実装候補は、確認済みの資料・通常関数の契約・実際の利用例から選ぶ。
未確認の語から新しい必須要件を作らず、同じ不成立候補を根拠なく繰り返さない。

将来の直接確認で意味が変わった場合は、該当行の設計判断と実装への影響を再評価する。
音声の確認票は未記入で保持する。独立利用者による試用も未実施であり、
保守者側の検査をその代わりにはしない。
講演全内容の完全実現という元の要求は未完了のままで、範囲を縮めて完成扱いにしない。

## 3業務の共通APIへ進む際の影響分類

原音の正確な発話は10件すべて保留のまま。以下は、それぞれが今回の実装を停止する理由になるかの分類である。

| 区間 | 実装判断への影響 | 進める根拠と保留する主張 |
| --- | --- | --- |
| iz-07 | 不変性の実装方針には影響するが、設計を進められる | 新しい値を返す状態遷移と、保存前の値・操作者の分離を例で検査する。readonlyの深い実行時保証や原発話の引用はしない |
| iz-08 | 新APIの契約への直接影響なし | 対象をバックエンド業務ロジックとするユーザーの明示要求・PDF24を根拠に進める。音声中の単語は保留 |
| iz-17 | I/O配置に関係するが、明示的な境界を設計できる | 同期のWorkflow、非同期のProcess、保存の分離を採用。Promise/Resultの資料に基づき、同期/非同期という原発話は断定しない |
| iz-27 | 保存の安全性に関係するが、特定ORMに依存しない契約を検査できる | 状態・outbox・receiptの同一transaction、競合、rollbackを実DBで検査。話者が特定の排他方式を指定したとはしない |
| iz-28 | 競合製品の説明への影響。実装の停止条件ではない | 外部ライブラリの機能不足を主張せず、依存ゼロというユーザー要件に沿う |
| qbf-05 | 型モデルの用語に影響するが、モデルは検査できる | 登録のawaiting/confirmed、休暇のpending/approved、検証済みの入力を具体化。音声の用語の確定は保留 |
| qbf-11 | 不要状態を減らす方向に関係するが、PDFで進められる | 登録の状態別必須項目・イベントの有無を直和で表す。否定表現の聞き取りは保留 |
| qbf-16 | 検証方針に関係するが、テストを続けられる | 型検査とは別に、権限・失敗停止・二重保存・rollbackを検査。テスト不要という解釈は採用しない |
| w0o-23 | 不正状態を減らす方向に関係するが、PDF55で進められる | 必須項目を状態ごとに定義し、外部から復元する値は実行時にも検証。すべての不正値を型だけで排除したとはしない |
| w0o-24 | 状態数の説明への影響。実装の停止条件ではない | 型の直和・直積の性質と実例を根拠にする。話者の増減に関する原文は保留 |

今回の3業務の共通APIで、未確認の音声だけを根拠に選ばなければならない設計分岐は特定されていない。原資料の完全確認は未達でも、これを理由に共通APIの実装・AI評価を止めない。実装の根拠は [3業務の評価](authoring-three-businesses.md) に分けて記録する。
