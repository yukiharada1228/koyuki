## Koyukiとの対応

forM_とUnion-Findは、不変な値を返す実装と、内部状態を変える実装を対比する説明例である。
Haskellでも命令的な記述が有用な場合を示しており、ループやclassを一律に禁じる要求とは解釈しない。
Koyukiでは普通の関数を使い、[ドメインとI/Oの境界](lecture-core-focus.md)を分ける。
Union-Findを内蔵したり、Haskell構文を再現したりするAPIを講演から必須機能として導かない。
図にあるコードは読み取ったもので、Haskell/OCamlの実行や正しさを検証したわけではない。

OCamlの例は、状態別に属性を分けるだけでなく、関連する属性を一つの任意の対にまとめている。
既存の在庫モデルの`lastAdjustment: { reason: string; by: string } | null`にも同じ構造がある。
[追加検査](../src/procurement-correlated-fields.test.ts)で、片方だけの履歴を型検査と復元処理で拒否することを確認する。
余分な属性を持つ変数はTypeScriptの構造的な代入では通る例も示し、保存値の閉じた形の検証とは区別する。

Member/GuestのUnionも、TypeScriptではそのまま排他的な和になるとは限らない。
[既存の反例と入力復元](../src/sum-model.test.ts)で、両IDを持つ変数の代入と、実行時の拒否を分けて検査する。
Tagの例は状態ごとに必要な属性を分けることに対応し、既存の[タグ](../src/tags/domain.ts)や
[購買の状態別モデル](../src/experiments/procurement/domain.ts)へ戻って照合する。
型の接続が成立することを、業務仕様の正しさや任意の入力の安全性の証明へ広げない。

## 抽出・再検査の範囲

映像は既存記録と同じSHA-256のローカルmp4を使う。
右上の192×108領域（x=1088, y=0）は除外し、11枚と17枚の一覧に全フレームを配置した。
元動画のPTSをffprobeで確認し、ffmpegで別途再復号したRGB画素のSHA-256と、全PNGの画素を照合した。
1,600枚すべてが一致する。原寸の全フレームを読み取ったという意味ではない。
全編動画・除外領域・直接音声の確認はこの追加作業に含めず、allFramesReviewed/audioDirectlyReviewedはfalseのままにする。
既存の直接音声確認が必要な10区間も、この画面確認で解決済みにはしない。

```sh
python3 scripts/check-lecture-frame-survey.py /path/to/functional-business-talks
```

再検査には、元動画と`frame-survey-84917b1`内の抽出PNG・一覧画像が必要である。
抽出はffmpegのss/t、drawbox、fps_mode passthroughを使い、間引いていない。
一覧の生成手順は同じローカルフォルダーのbuild-contacts.pyに保存している。
Python/Pillowとffmpeg/ffprobeは資料検証用の開発ツールで、製品のruntime依存ではない。
検査器は原資料のhash、時刻・画素の一致、一覧の範囲を検査する。記録の内容を人が読み取ったことや、解釈の正しさを自動証明しない。
欠けた区間、異なる原資料hash、画面全体の除外、一覧の欠落、全編確認済みへの書換えを拒否する対照例も実行した。
さらに別時刻のPNGを先頭へ置き、メタデータのhashまで更新した対照例も、元動画との画素比較で拒否した。
