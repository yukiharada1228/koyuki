# 経費の遷移列を独立仕様と照合する

開発時の[探索テスト](../src/expense-state-exploration.test.ts)で、経費の宣言した遷移と独立した参照仕様を比較する。
期待結果の計算にはdomainの検証・経路選択・遷移・保存条件を呼ばない。
実装側は既存のsubmitted/approved/rejected/returned/editedをtransitionで実行する。
業務runtimeの宣言APIや実行時依存は増やさず、開発版の検査専用入口を利用する。

対象は申請、上長・経理承認、却下、差戻し、編集。金額3000/3001/100000/100001、
領収書の有無、所有者・複数の上長・経理・非アクティブな利用者・自己承認、空の理由、
不正な編集金額を組み合わせる。初期draftは8通り、各状態に128通りの操作を適用する。

[koyuki/testingの有限探索](finite-model.md)で最大7操作まで幅優先に探索し、状態の全フィールドと承認証跡をキーに訪問済み状態を統合する。
versionも保持するため、差戻しから再申請した状態を初回申請と同一視しない。
同一状態への失敗操作は再投入せず、その成否とエラー種別を照合する。
各成功では次状態の全内容、元状態の非変更、restoreExpenseとの往復、保存境界の遷移条件も検査する。
差戻し・編集・再申請と複数回の差戻しに到達することを検査し、探索件数をテスト出力へ記録する。

```sh
npx tsx --test src/expense-state-exploration.test.ts
```

不一致時は初期状態とそこまでの操作列を出力する。幅優先で各状態の最短到達列を保持するが、
任意の失敗条件に対する汎用的な縮小器や乱数seedを備えるものではない。
現在の純粋な遷移は入力の現在状態と操作から決まるため、この全状態キーで同一状態をまとめている。
履歴・外部IO・時刻に依存する業務へ同じ統合条件を無検証で適用しない。

これは有限の入力集合・深さに対する経費の実装照合であり、任意金額・無限の編集回数・
DB競合・永続化・副作用・独立利用者の開発体験を証明しない。
編集・再申請を含む探索結果はkind: limited、limits: ['depth']。同一モデルの無限version列を検証済みとはしない。
有限探索とは別に、[seed付き操作列と縮小](model-sequences.md)も提供する。
Issue #8全体の完成、一般的なモデル検査の導入効果、講演全内容の完全実現とは扱わない。

参照仕様・入力生成・実装比較は[model-testing.ts](../src/expenses/model-testing.ts)に置き、
既存の探索・到達確認・反例検査と[雛形から生成したテスト](model-test-template.md)で共有する。
生成時には業務moduleを実行せず、テスト時に利用者指定の仕様とドメイン処理を比較する。
実tarballのconsumerでも生成した3 seedのテストを型検査・実行する。

## 一回の承認過程の有限グラフ

別の検査では、同じ独立仕様から編集イベントだけを除き、申請・承認・却下・差戻しを探索する。
初期8状態・各状態48操作の有限集合で、37状態・1,776操作を上限による打切りなしで探索し、
kind: passedとなる。versionや承認者の情報をkeyから落として有限化したものではない。
編集を含まないため差戻しから再開しないという、このイベント集合に限ったモデルである。
元の全操作モデルを置き換えたり、差戻しを業務全体の終端へ変更したりしていない。

不変条件は保存された上長・経理の承認証跡に所有者が現れないこと。
小額の自動承認には人の承認者がいないため、所有者による申請を自己承認と混同しない。
承認待ちでの所有者による承認要求15件がSelfApprovalとなり、状態が変わらないことを照合する。
approved/rejected/returnedでの承認要求192件はInvalidStateで、状態が変わらないことも照合する。
すべての辺を実装と独立仕様で比較するため、これらの性質をモデルだけの確認で終えない。

検査の感度を確かめるため、モデル側の上長承認で所有者を許す意図的な変更も試す。
この場合は実装比較を無効にしても不変条件が反例を返し、イベント列は申請→自己承認となる。
意図的に壊したモデルはテスト内の局所的な値であり、業務実装には適用しない。

対象外は任意の金額・操作者集合、編集を含む無制限の繰り返し、DB、外部認証、並行実行。
passedは上記の有限グラフに限る。実tarballのkoyukiとkoyuki/testingを使うconsumerでも同じ探索を実行する。
