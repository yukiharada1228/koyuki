## 履歴の話と永続基盤の要求を混同しない

w0o-13では、明示した引数と戻り値から途中状態を調べられることと、履歴を取りたい場合に
それらをdumpできることが説明されている。フレームワークが既定で全データを永続収集し、
任意の保存先や保持期間まで自動決定するという仕様指定としては読まない。
SQLiteの成功変更metadata監査も、この全値dumpと同じものではない。

選択captureは観測の具体化として検証できた。一方、全引数・戻り値の保存先・項目・保持・削除は
依然としてKoyukiの運用上の未提供範囲として記録する。これらを講演で指定された必須仕様へ
読み替えたり、今回のテストで永続履歴まで完成したと扱ったりしない。

今回の全25操作の比較では、正常時に96記録を確認する。
全入力射影または全Result射影をthrowさせる場合は96件のCaptureFailedを確認し、
保存済み成功を観測失敗へ置き換えない。診断のために業務処理を再実行もしない。
業務失敗経路は従来の代表例で検証しており、全状態・全失敗・全故障箇所を網羅したという意味ではない。

## 判定

今回の変更は、未使用の宣言を除くことと、既存の観測契約の検証範囲を広げること。
新しい業務DSLや自動永続履歴APIを追加していない。
全講演の完全実現・一般的な性能優位・独立利用者の生産性向上は確認できておらず、
[要件別判定](lecture-acceptance.md)は部分充足を維持する。
