# 独立したフィールドのResultを漏れなく集約する

collectは、評価済みの独立したResultを通常のrecordで受け取り、成功時には値のrecord、
失敗時にはフィールド名とエラーの一覧を返す。後続の業務計算は通常のRuleとして接続する。
集約自体は新たなI/Oを実行せず、Resultを生成した計算の順序や再実行も管理しない。

開発版では、列挙されないownデータフィールドも漏らさず集約する。
数値キーのエラー名はJavaScriptの実際の文字列キーとなり、型でも0ではなく'0'を返す。
各フィールド名とそのエラー型の対応は維持する。
通常のrecordとnull-prototype recordを受け付け、Symbolキー・getter/setter・custom prototypeは
構築時に拒否する。構造的なTypeScript型だけではdescriptorや所有権を表せないため、
型が通るすべてのJavaScript objectを受け入れる契約ではない。

全descriptorを確認してからResultを読み、拒否するテーブルのgetterを実行しない。
入力テーブル・domainの値やエラーをfreeze/cloneせず、値とエラーの参照を保つ。
生成する成功record・エラー一覧は従来どおりfreezeする。
Symbolを含むdomain値を禁止するものではなく、集約するフィールドのキーへの制約である。

fe64125の修正前には、列挙されない失敗ResultやSymbolキーの失敗Resultがあるのに
collectがok({})を返すことを再現した。
[回帰検査](../src/collect-fields.test.ts)は非列挙の成功・失敗、数値名、全フィールドの事前検査、
null prototypeとprototypeに似た名前を確認し、実tarballの独立consumerにも含める。

## 講演の主張と実装要件を分ける

実装基準fe64125a0d4c308c575522cfa48d838242a2be97で、保存済み字幕の
qBf910_YiqA 26:02–28:01とizV1h6o3hgQ 73:53–74:40を再読した。
原文の同一性は既存manifestに記録したhashで検査する。新たな音声・全画面のレビューではない。

| 主張・残項目 | 判断と検証する対象 |
| --- | --- |
| 独立したResultをまとめる負担 | ライブラリで扱える具体的な実装要件。collect等で集約し、今回のフィールド欠落を修正する |
| Resultのための言語的支援がない | TypeScript構文の制約。ライブラリだけでdo記法や透過的なResult構文を実現したとは言わない |
| 純粋な関数はテストしやすいがResultの取り出しが定型になる | テストの記述負担の指摘。専用DSLの指定ではない。既存検査はResult全体の比較、必要な場合の明示的な判定・取り出しを使う。負担の削減や独立利用者の評価は未実証 |
| React/Elmに近い書き心地、チームの学習・速度・障害の評価 | 実証が必要な主張。機能数・テスト件数・maintainerの成功で代替しない |
| 実メール・scheduler・保持と削除 | ホストの選択と運用検証が必要。サンプルの成功を全providerの保証に一般化しない |

この整理によって既存のpartial判定を引き上げない。専用DSLを足すこと自体を目的とせず、
実装上の欠落と、言語・ホストの境界、未取得の実証を区別する。
全講演の完全実現や全編音声との照合は引き続き未確認である。
