JSXなしの設計への移行

公開入口からJSX用のexportを外し、experimental-jsx.tsへ分離。
タグ作成・編集と公開利用例を.tsに変更。通常の処理でrenderを指定しない。
古いTagProcessとJSX実験は比較テスト用に保持する。

Workflow.branchを追加。
失敗ならpredicateも分岐先も実行しない。
成功時に選んだ一方のWorkflowだけを評価する。
出力型と失敗型をunionとして保持し、選択した経路を記録する。

例: src/examples/expense.ts
3000円以下は自動承認経路。それを超えると領収書が必須。
10万円以下は上長、それを超えると上長と経理の承認が必要な経路を選ぶ。
承認要件を判断する例であり、人間の承認完了を扱うものではない。
Repositoryはポートのみで、本番用DBアダプターや画面は未実装。

検証
npm run check: 成功
npm test: 209件成功（今回追加10件）
金額の境界、選択しない分岐の未評価、領収書不足での停止、入力検証、
保存を一回だけ呼ぶこと、競合の伝播、出力・失敗型のunionを検証。
HTTP/TCPとSQLiteを含む既存テストも成功。
UI変更はないため今回はブラウザー再操作なし。

発見と制約
この例では通常のTypeScriptで入れ子の業務判断を表せる。
JSXの必要性を示す根拠はまだ得られていない。
branchのyes/no自体は入力型の絞り込みを行わない。
predicateの純粋性はTypeScriptが保証するわけではない。
stepsは直列部分の概要であり、分岐を含む完全な静的グラフではない。
分岐後の処理では出力のunion全体を扱う必要がある。
